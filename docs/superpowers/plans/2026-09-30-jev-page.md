# Jev Page Implementation Plan

> Executed inline (superpowers:executing-plans) at the user's request. Steps use `- [ ]`.

**Goal:** A "Jev (fast decisions)" sidebar page: one-click install of TypeSafe's Claude Code plugin, the Jev API key saved into Claude Code settings, and an honest "where Jev fits" card.

**Architecture:** New `finops/jev.py` (plugin status/install/uninstall via the `claude` CLI with fixed argv, key in `~/.claude/settings.json` `env`, read-only fit query). Three routes in `finops/api.py`. One view in `web/app.js` reusing `doAction`, `followJob`, `card`, the `.cfg` form styles.

**Tech Stack:** Python 3 stdlib + unittest; vanilla JS module; no new dependencies.

**Spec:** `docs/superpowers/specs/2026-09-30-jev-page-design.md`

## Global Constraints

- Plain language; Jev described honestly ("doesn't make Claude Code itself cheaper").
- Never run the real `claude plugin install/uninstall` or write a real key during development; tests mock subprocess and point `integrate.SETTINGS` at a temp file.
- Processes started while verifying are stopped by their own PID only — no `pkill`/`killall` by app name, never quit the user's apps.
- Commits: `git -c user.email=mohitrj49@gmail.com commit`, message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. The user's popover change is stashed for the whole run.

## Review Focus

1. A settings.json with other `env` entries (e.g. proxies) — save/remove must keep them.
2. `claude` missing from PATH or `plugin list --json` printing non-JSON — status must degrade, not 500.
3. Marketplace already added — install must continue to the plugin install.
4. "Hide prompts" on — fit examples must not show prompt text.
5. Key typed with a trailing newline/space from copy-paste — strip, then validate.
